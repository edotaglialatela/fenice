IO - VTK output and checkpoints

VTK output

VTKExporter writes ParaView-readable VTK XML in ASCII. Every file is written to <file>.tmp and then renamed, so ParaView never sees a partially written file, even if the run is interrupted mid-write.

  • Uniform mesh. One RectilinearGrid <case>_<step>.vtr per snapshot, with the cell fields Density, Pressure, Temperature_nondim ($p/\rho$), Mach and Velocity (3 components). A 2-D grid is one cell layer (z extent 0 0, $w = 0$); a 3-D grid has the z coordinates $0 \ldots L_z$ and the real $w$.
  • AMR. One .vtr per leaf patch in a step subfolder (<case>_<step>/p0000.vtr, …), grouped by <case>_<step>.vtm (vtkMultiBlockDataSet). The extra AMR_Level field holds the refinement level.
  • Time series. write_pvd writes <case>.pvd with one entry per snapshot (the .vtr or the .vtm).

Values are sanitised for ParaView's float32 parser: NaN becomes 0, ±Inf becomes ±$10^{30}$, and $|x| < 10^{-30}$ becomes 0. The validation/ scripts parse these files directly with xml.etree.

Checkpoints (.npz)

Checkpoints are NumPy .npz archives (uncompressed zip of .npy arrays), written and read without third-party libraries, so numpy.load reads them directly:

Key Content
U state, (nx*ny, 4) float64 in 2-D, (nx*ny*nz, 5) in 3-D (columns $\rho, \rho u, \rho v, \rho E, \rho w$)
t, step physical time and step
nx, ny, Lx, Ly grid metadata (makes checkpoints self-describing for hot start)
nz, Lz grid depth (nz = 1 for 2-D; missing in older files, read as 1)
collection_time, collection_file .pvd index, restored on resume

The reader handles zip64 headers as written by numpy.savez. Archives that store the .pvd index as a pickled collection object instead of the two arrays are also accepted for resume and hot start; the pickled index is skipped. Compressed archives (savez_compressed) are rejected with an explicit error.

import numpy as np
d = np.load("results/sod_shock_tube/sod_shock_tube_restart.npz")
rho = d["U"][:, 0].reshape(int(d["ny"]), int(d["nx"]))
# 3-D: rho = d["U"][:, 0].reshape(int(d["nz"]), int(d["ny"]), int(d["nx"]))

Monitor (monitor_interval)

With monitor_interval = N > 0, the run appends one line every $N$ steps (plus the first and last step) to <case>_monitor.csv:

step,t,mass,kinetic_energy,total_energy

The three columns are cell averages of $\rho$, $\tfrac12\rho|\mathbf u|^2$ and $\rho E$ over the whole domain. Under MPI they are all-reduced, so the file matches the serial one. The monitor is much cheaper than snapshots for integral histories. The 3-D Taylor-Green validation computes its dissipation rate $-dE_k/dt$ from it.
